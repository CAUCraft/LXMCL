# 信息架构与需求映射

依据项目功能需求整理，保留原文编号。此表覆盖产品目标，**不表示各项已实现**；当前交付边界见 [接力开发](../development.md)。视觉与动效以 [当前设计规范](visual-design.md) 为准。

## 1. 先按任务分区，再按熟练度展开

主导航固定为 **开始游戏、社团联机、我的游戏、资源中心**。账号与装扮、下载任务、设置、帮助和诊断使用固定辅助入口。不要把原文的“基础 / 高级 / 辅助”直接做成三个页面：用户通常知道自己要做什么，并不知道某个功能被开发者归为哪一类。

| 一级入口 | 用户来这里要完成什么 | 二级分区 | 首页的快捷入口 |
|---|---|---|---|
| 开始游戏 | 尽快启动已有游戏、继续上次游玩 | 当前游戏、当前账号、启动状态、最近游戏、新手引导 | 主启动按钮、社团服卡片 |
| 社团联机 | 找到服务器并进入、与朋友联机 | 社团服务器、服务器详情、兼容游戏、入服准备、临时联机房间 | 准备并进入 |
| 我的游戏 | 创建、选择和管理已安装的内容 | 游戏列表；选中游戏的概览、模组、资源包、光影、世界、设置；更多操作 | 最近游戏、创建 / 导入 |
| 资源中心 | 找到新的线上资源并安装 | 模组、整合包、资源包、光影、世界；来源、版本、加载器筛选 | 全局搜索结果跳转 |
| 账号与装扮 | 登录、切换身份、管理皮肤和披风 | 我的账号、认证服务、角色、皮肤站衣橱、本地装扮导入 | 当前账号卡片 |
| 下载任务 | 知道在下载什么、处理失败和等待 | 进行中、已完成、失败；任务分组、依赖、重试、暂停 / 继续 | 全局任务计数 |
| 设置 | 修改启动器默认行为与运行环境 | 常规与启动、外观与无障碍、游戏默认配置、Java 与存储、下载与网络、扩展与自动化、关于与更新 | 全局搜索可直达具体设置 |
| 诊断与工具 | 解决启动或网络问题 | 游戏诊断、日志与诊断包、网络连通性、系统工具、高级诊断 | 启动错误和下载错误旁的修复入口 |
| 帮助中心 | 学会一个操作 | 开始游戏、账号登录、社团入服、资源管理、常见问题；全文检索 | 新手引导、每个错误的相关教程 |

**首页不是控制台全集。** 只展示一个当前游戏、一个当前账号、一个主要启动动作与社团入口。Java、内存等只显示“已就绪 / 需处理”，点击后再进入相应设置。

### 几个容易混淆的边界

1. **资源中心 = 找到新内容；我的游戏 = 管理已经安装的内容。** 在我的游戏中点击“获取模组”，跳到资源中心并保留目标游戏与兼容筛选；安装完成后提供“查看已安装资源”。
2. **游戏版本不等于实例。** 面向用户统一叫“我的游戏”；在创建界面和帮助中解释“每个游戏拥有独立的版本、模组与存档”。高级文案可以补充“游戏实例”。
3. **材质包统一显示为“资源包（材质包）”。** 模组、资源包、光影、世界和整合包分开；皮肤与披风归账号装扮，避免误装进游戏目录。
4. **Java 是运行环境，不作为主导航。** 缺少环境时从启动任务内引导安装；完整版本列表在设置中。
5. **全局默认和当前游戏配置分开。** 实例设置每一项都显示“继承全局”或“已单独设置”，可逐项恢复继承。全局修改页提示已有多少个实例覆盖了这一项。
6. **启动器下载代理和游戏进程代理分开。** 前者在“下载与网络”；后者在当前游戏的高级运行设置。显示影响范围，避免用户改错对象。
7. **社团账号是明确的认证入口。** 在认证协议确认前，不把它写成“学校统一身份认证”，也不假定某种真实账号一定能进入某个服务器。
