# 信息架构与需求映射

依据项目功能需求整理，保留原文编号。需求表覆盖产品目标，**不表示各项已实现**；当前交付边界见 [开发指南](../../../../docs/development.md)。视觉与首页禁令以 [REDESIGN.md](REDESIGN.md) 为准；[资源与渲染约束](visual-design.md)仅维护资产保护与性能边界。

## 1. 页面与任务归属

导航尺寸与布局以 [REDESIGN](REDESIGN.md) 为准；本表映射任务入口，内部整数路由不作为设计依据。

| 入口 | 上下文与任务 |
|---|---|
| 主页 | 版本选择、启动、实例目录 / 设置；无实例时进入创建或安装流程 |
| 版本 | 我的游戏 / 资源 / 任务；进入实例后替换为概览、模组、资源包、光影、世界、设置、日志 |
| 联机 | 服务器 / 联机房间；兼容实例与入服准备 |
| 设置 | 常规 / 游戏 / Java / 网络 / 外观 / 账号 / 扩展 / 关于 |
| 右上账号 | 切换、添加和账号装扮；真实认证能力单独接入 |
| 工具入口 | 搜索、帮助、诊断、首次向导和准备流程，保留返回上下文 |

下表原需求中的「我的游戏」对应版本页，「资源中心 / 下载任务」对应资源 / 任务分类，「社团联机」对应联机页；账号、教程和诊断在各自上下文可达。正常首页只保留四项启动操作，问题在对应流程提供修复入口。

### 几个容易混淆的边界

1. **资源中心 = 找到新内容；我的游戏 = 管理已经安装的内容。** 在我的游戏中点击“获取模组”，跳到资源中心并保留目标游戏与兼容筛选；安装完成后提供“查看已安装资源”。
2. **游戏版本不等于实例。** 面向用户统一叫“我的游戏”；在创建界面和帮助中解释“每个游戏拥有独立的版本、模组与存档”。高级文案可以补充“游戏实例”。
3. **材质包统一显示为“资源包（材质包）”。** 模组、资源包、光影、世界和整合包分开；皮肤与披风归账号装扮，避免误装进游戏目录。
4. **Java 是运行环境，不作为主导航。** 缺少环境时从启动任务内引导安装；完整版本列表在设置中。
5. **全局默认和当前游戏配置分开。** 当前实例设置页仅展示继承全局的配置，并提供独立的修改全局入口；逐项覆盖 / 恢复继承尚未实现。后续每一项应显示“继承全局”或“已单独设置”，并提示受影响范围。
6. **启动器下载代理和游戏进程代理分开。** 前者在“下载与网络”；后者在当前游戏的高级运行设置。显示影响范围，避免用户改错对象。
7. **社团账号是明确的认证入口。** 在认证协议确认前，不把它写成“学校统一身份认证”，也不假定某种真实账号一定能进入某个服务器。
