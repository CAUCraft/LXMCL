# LXMCL UI 最终设计规范 · 日光 04

2026-11-02，当前设计与实现约定。首页风格及合并顶栏已获确认，内部工作区按用户最新要求继续桌面化。**设计决定不等于原生实现完成或人工验收通过。** 本文件集中维护布局、控件、状态与动效；[日光 04 原型](prototype.md)保留为首页风格参考，内部布局以本规范与原生实现为准。原型 HTML / JS 不进入 Rust + Slint 应用运行链。实现进度见[开发指南](../../../../docs/development.md)；检查结果在交付说明 / PR 中报告。

## 1. 产品与窗口

LXMCL 的日常任务是选择确切实例并启动 Minecraft。Windows 11 原生窗口行为优先，采用 Apple 式留白与克制、明亮河谷和局部轻透表面。Windows 将最小化、最大化 / 还原、关闭合入现有导航顶栏，移除重复的系统标题栏；其他平台采用系统装饰回退。必须分别验证拖动、双击、窗控、缩放、Snap、系统快捷键、任务栏和多 DPI。不仿造 macOS 三色窗控，不把任务栏或整张参考 UI 绘入应用，不声称已有系统 Mica 或实时模糊。

合并顶栏保持单行：品牌、四主 Tab、账号、右侧三枚窗控。仅品牌和空白区域可拖动、双击最大化；导航、账号与窗控不触发拖动。关闭使用正常窗口关闭流程，让已接受写入和插件退出清理继续执行。窗口边缘保留逻辑像素缩放区域，最大化时关闭边缘缩放；按钮避开该区域。窄窗口可收起账号名称，头像、菜单与窗控保持可达；账号浮层对齐账号入口。窗控使用线条图标、可见焦点、名称和 tooltip，关闭悬停为红色；绘制在账号、搜索及弹窗遮罩上方，同时保留统一快捷键和弹窗焦点规则。默认 Shell 的窗口实现不进入业务插件 API。

默认静态背景是独立的[河谷素材](../../../../ui/assets/daylight-river.png)，按 cover 裁切，不扭曲；内部工作区采用纯净画布、紧凑工具栏和属性表，风景只用于首页。动态壁纸只在外观设置中按需启用，已有选择和 LFS 资源保留。原 Logo 与孪枭皮肤字节不变，不新增航空 / 航天意象。

## 2. 导航与信息架构

顶部固定四个主 Tab：**主页 / 版本 / 联机 / 设置**；品牌在左，账号头像和名称在右。禁止新增一级入口或常驻侧栏。主页不显示二级栏；其他页面共用**唯一 ContextNavigation**，位置、高度、选中底和键盘语义一致，不再叠第二排页面标签或设置侧栏。

| 当前任务 | 同一条上下文栏 | 内容 |
|---|---|---|
| 版本 | 我的实例 / 资源 / 任务 | 完整实例列表、资源筛选、任务列表 |
| 实例详情 | 返回 + 实例辨识 + 概览 / 模组 / 资源包 / 光影 / 世界 / 设置 / 日志 | 详情替换列表；导航替换原版本分类，不叠加 |
| 联机 | 联机 | 当前未启用；后续插件提供服务器、房间或社团服务 |
| 设置 | 常规 / 游戏 / Java / 网络 / 外观 / 账号 / 扩展 / 关于 | 分类直接进入表单；无额外侧栏 |
| 帮助与诊断 | 返回 + 帮助 / 诊断 | 工具按钮进入，保留 Ctrl+K 与 F1 |

实例返回列表恢复搜索、滚动和焦点；资源类型是 Select 筛选条件，不增加页面标签。账号、皮肤、资源、下载、诊断、教程、首次向导和搜索保留。社团功能移出默认流程，专属教程 ID 与素材保留供后续插件使用；不能把未实现服务包装成已加载插件。旧整数路由属于兼容实现，不能反过来定义设计。完整需求编号见[信息架构](information-architecture.md)，安全流程见[交互规范](interaction.md)。

实例行单击或 Space 选择启动目标，方向键在列表移动选择，Enter / 双击打开管理，F2 重命名。行尾管理、目录及重命名按钮按该行 ID 操作，不触发行选择。`selected` 是首页启动目标，`inspected` 是详情目标；搜索、任务或扩展打开详情不修改启动目标，显式启动详情实例才切换启动目标。返回恢复被浏览行的焦点，若筛选排除了该行则返回搜索框。详情用名称、版本、加载器、目录属性行呈现，所有操作保持同一详情 ID。

## 3. 首页：四项操作

首页只有风景和右下轻透启动面板：**版本选择器、绿色「启动游戏」、打开游戏文件夹、当前实例设置**。两项工具操作使用图标、tooltip、可访问名称与可见焦点。正常首页没有实例标题、存档切换、准备就绪、最近游玩、常驻下载 / 网络状态、欢迎语、新闻、公告、推荐、社团宣传或统计。存档在实例详情 / 游戏内管理。

选择器展示 `1.21.1 · Fabric` 等标签，业务绑定唯一 `instance_id`；重复版本 / 加载器在下拉内显示实例名称或 ID 区分。候选来源是完整实例集合，不能受管理页搜索过滤。切换后重建目标上下文，不复用其他实例的旧报告。

| 状态 | 展示与动作 |
|---|---|
| 正常 | 四项操作；唯一绿色启动主动作 |
| 没有实例 | 「尚无实例」与「创建实例」；主动作直接打开配置表单，不称已安装游戏 |
| 检查 / 启动忙碌 | 当前操作显示阶段，防重复提交；可离开页面 |
| 缺 Java / 认证失效 / 准备失败 | 在对应流程显示具体原因、目标、修复 / 重试 / 教程入口 |
| 路径错误 | 说明实际目标与失败原因，不改用其他实例目录 |
| 演示能力 | 操作区域说明演示；不能靠计时器、假日志或虚构在线状态声称真实成功 |

## 4. 逻辑像素、颜色与布局

以下数值来自批准的日光 04，均为逻辑像素；通过 Slint 布局约束适配，不把全页写成绝对坐标。原型最小场景 960×560、常用 1200×700；原生最小窗口与 DPI 以实际容纳能力和验证结果为准。窄窗二级栏允许横向滚动，不丢入口。

| 元素 | 基线 |
|---|---|
| 应用导航 | 高 62，左距 26；主 Tab 高 38、圆角 12、项间距 8 |
| 上下文栏 | 高 44，左右距 16；选中项高 32、小圆角及细下划线，标签可横向滚动，返回与工具固定 |
| 正文 | 常规页边距 20、组间距 12；设置内容宽约 800，居中；工具栏与底部应用栏固定 |
| 首页面板 | 宽 374，右 / 下距 28，圆角 26；内距上 / 左 / 右 26、下 15 |
| 版本选择器 | 高 48，圆角 13，文字 16 |
| 启动按钮 | 高 57，圆角 14，文字 19，距选择器 22 |
| 首页工具区 | 距主按钮 16，每项高 48，图标 24，中间细分隔 |
| 普通控件 | 高 32、圆角 6；IconButton 命中区至少 34；首页控件保持独立的大尺寸 |
| 分组 / 浮层 | 分组圆角 8、内距 16；重命名对话框约 440×260，内容和错误可撑高；创建对话框约 520×400 |
| 文字 | 正文 12–14，工作区标题 17、分组标题 14；Microsoft YaHei UI 等系统字体回退 |

| 语义 Token | 浅色基线 |
|---|---|
| 正文 / 辅助 / 弱化 | `#202936` / `#697482` / `#78818C` |
| 画布 / 面板 / 控件浅底 | `#F1F5F9` / `#FFFFFFDE` / `#E7EDF3` |
| 边缘 / 顶栏 | `#243C5517` / `#E8F1FD` |
| 中性强调 / 选中底 | `#49637D` / `#DDE8F2` |
| 启动绿色 | `#159738` → `#0B8035`，仅突出首页启动动作 |
| 焦点 / 危险 | 蓝色可见轮廓 / 红色文字与图标，均配语义提示 |

Token 统一进入 `ui/theme.slint`；明暗使用同一语义映射，不能每页维护色值副本。暗色要验证文字、焦点、禁用、错误与背景对比度。轻透可用低成本叠层近似；原型 CSS blur 不构成原生必须实现的系统特效。重要错误和对话内容优先可读性。

## 5. 共享控件与容器

默认 Shell 提供 Button（普通 / 无边框 / 主动作 / 危险）、IconButton、TextField / SearchField、Select、SegmentedControl、Toggle、Slider、Stepper、SettingRow / Group、ListRow、Disclosure、Popover、Sheet、Notice / Empty / Task。页面配置内容和回调，不自建不同风格的按钮、导航和窗口。

- 每个控件都有默认、hover、按下、禁用、焦点与必要的忙碌 / 错误状态；选择态与焦点态区分。图标有名称和 tooltip，不能靠颜色独自表达状态。
- Select 与菜单支持方向键、Enter / Space、Esc、关闭返回触发点；分段选择单一 Tab 停靠，支持方向键与 Home / End；Toggle 支持 Space，Stepper 夹取范围，Slider 有最小 / 最大 / 步长与键盘操作。
- SettingRow 至少高 40、分组内距 16，标签左、控件右；实例行高 64。选择与键盘焦点分开呈现。描述只解释作用范围和后果，不用装饰说明填满页面。
- 详情及表单使用同一居中 Sheet：标题、内容、底部操作、焦点约束、Esc、关闭后返回触发位置。换步骤不重播容器入场；避免一处居中弹窗、一处侧出抽屉。
- 搜索只更新列表；表单值变化不重建页面。设置草稿跨分类保留，固定底部「应用设置」保存界面和游戏偏好；Java 验证及选择立即保存，页面说明作用范围。撤销草稿、未保存提示及实例逐项覆盖尚未实现，不提前展示无效控件。
- Tab / Shift+Tab、Enter / Space、Esc、Ctrl+K、F1、Alt+Left 形成一致路径。危险确认默认取消，不把输入框 Enter 当作删除授权；错误提供修复入口。

## 6. 有界、可打断动效

统一缓动 `cubic-bezier(.22,.8,.24,1)`；原生采用可验证的等价曲线。快速切换只追随最新目标，旧完成回调不能覆盖新状态。禁止逐项错峰入场、回弹、长尾、无限动画和拦截滚轮制造惯性。

| 对象 | 行为 | 时长 |
|---|---|---|
| hover / 按下 | 表面颜色；普通按钮不缩放 | 90 ms |
| 一级选中底 | 从当前位置连续移至最新目标；二级使用即时选中底与细线 | 190 ms |
| 旧内容 | 最多一层、仅淡出，保持原截止时间 | 170 ms |
| 新内容 | 仅短透明度过渡；内容和导航不位移 | 100 ms |
| Sheet 打开 | 透明度 + 9 px 位移 + 0.99 起始缩放 | 210 ms |
| Sheet 关闭 | 透明度 + 3 px 轻退场 | 100 ms |
| 菜单 | 透明度 + 最多 3 px 位移 | 160 ms |
| 展开 / 收起 | 当前实际高度接续至最新目标 | 180 ms |
| Toggle | 当前滑块位置接续，底色过渡 | 150 / 120 ms |

退出层不可点击、不可聚焦、对辅助技术隐藏，结束即释放。原生 Slint 不照搬 DOM 副本；若使用临时绘制层，数量必须有界且不能保留旧业务对象。减少动态效果立即终止过渡、清理退场层并采用最终状态，优先于慢速观察。闲置停表，不可见皮肤 / 视频停更或降频，列表增量更新。模型检查只能证明目标和取消正确，流畅度仍需帧时间、输入响应、空闲 CPU 与长期驻留检查。

## 7. 插件与业务边界

默认 Shell 统一提供导航、控件、浮层、焦点、错误和运动策略。插件向版本、联机、设置等既有任务贡献动作、内容或设置分组，使用稳定贡献 ID 与宿主提供的目标上下文；不能自行增加全局主 Tab、持有过期实例、重复搭建全局弹窗或绕过能力校验。整套 UI / Shell 可以由产品装配替换，不能把 Slint 类型和视觉布局泄漏成运行时服务依赖。具体插件 API 与生命周期以[平台架构](../../../../docs/architecture.md)和[插件文档](../../../../docs/plugins.md)为准；这里不承诺运行时安装、沙箱或热重载。

社团服务器、公告和专属认证属于后续扩展，基础产品不启用相关演示入口。先完成通用实例、账号、Java、安装与启动能力，再按真实需求增加对应插件，不为社团预建空服务或专用路由。

Rust 服务契约不因换皮削弱。`LaunchContext` 绑定实例、账号、目录、版本与配置修订；未知结果不放行，旧报告失效，幂等请求防重复。阻塞 I/O 由后台桥执行，再回 Slint 事件循环。当前真实 / 演示能力见开发指南，不能从原型推断下载、认证、Java 安装、诊断和启动已经接真实服务。原需求、安全确认、教程 ID 和[服务契约](service-contracts.md)持续有效。

## 8. 实施与验收

按[架构设计](../../../../docs/architecture.md)逐功能完善插件边界，在默认 Shell 的共享 Token / 控件 / 导航上迁移；功能入口覆盖后再移除旧兼容外观与路由。源码迁移、构建和窗口验收分别记录，不能用设计决定勾选运行时验收。

- 首页恰好四项操作、四主 Tab、单一上下文栏、详情替换列表、八类设置和统一 Sheet。
- 唯一实例选择、重复版本辨识、无实例、认证 / Java / 准备失败、忙碌、重试与焦点返回均走通；演示有明确边界。
- Windows 原生拖动 / 最大化 / Snap / 快捷窗口操作；960×560、1200×700、1366×768、1920×1080 与 100 / 125 / 150% DPI 检查重叠、裁切和导航可达性。
- 明暗、键盘、减少动态效果、快速 A→B→C、浮层反复开关、长列表滚动、空闲停表与帧时间分别复验。
- 按范围执行 fmt、Rust 测试、clippy 和 build，记录实际结果与未执行项；纯文档无需编译。编译通过不等于视觉、读屏或性能验收。

优先级：用户最新决定 → 本规范 → 唯一 UI Skill 的执行流程 → 其他文档业务要求。旧版本设计资料由 Git 历史追溯，不再保留互相冲突的候选规范。
